# 🎬 Awesome-Video-Action-Models

Video action models grounded in video prediction, video generation, and world-action modeling demonstrate strong potential in embodied control. They can serve as video-conditioned policies, joint action-world generators, unified foundation models that support mixed training with action-labeled trajectories and action-free videos, and bridge mechanisms from human or action-free video to executable robot behavior.
This repository summarizes recent research on **video action models (VAM)**, **world-action models (WAM)**, and **video-to-robot bridge signals** in embodied AI.

## Scope and reading guide

**Coverage update: 2026-10-05.** Added **193 papers** after comparison with a local paper library: **162 first submitted in August-October 2026** and **31 June-July backfills**. October coverage reaches the papers available in that library through **October 2**, not the whole month. The README now links **470 distinct arXiv records**, plus non-arXiv resources. Counts use unique arXiv IDs, not repeated rows in the thematic views. See the [Chinese coverage audit](docs/coverage-audit-2026-10-05.zh-CN.md) and [screening record](docs/coverage-screening-2026-10-05.json).

Include a work when it provides a concrete **predictive world-to-action interface**, **joint world/action learning**, **video-derived action or geometric supervision**, or a directly relevant **world-model training, execution or evaluation mechanism**. Generic VLA, action tokenization, memory, RL and coding-agent papers are not automatically VAMs. Adjacent driving works are labeled `driving`.

The four routes are reading aids and can overlap. R1 emphasizes a predictive or video-derived interface before control; R2 emphasizes coupled world/action generation; R3 covers unified interfaces and world-supervised direct policies; R4 covers supporting mechanisms and evaluation. A row's **deployment/use** label is more informative than its route alone:

| Label | What remains when the system is used |
| --- | --- |
| `Predict-then-act`, `Predictive features`, `Persistent plan` | A predicted goal, representation, trajectory or retained plan conditions action generation; it need not be rendered as RGB. |
| `Coupled`, `Coupled latent`, `Coupled + feedback` | Action and predictive quantities are generated in a coupled policy; tactile feedback can additionally revise execution. |
| `Async` | Predictive context and action updates run on different schedules; check what gets refreshed and which actions are already committed. |
| `Train-only` | The relevant future-prediction target/branch is used for learning but is omitted from deployed action generation. |
| `Direct predictive features`, `Direct action` | Current-conditioned features or a one-pass cache support direct action generation, without iterative future rollout. Read the row for the remaining predictive interface. |
| `Current denoising` | Generative adaptation uses the current observation; this is a boundary/control case for the necessity of future targets. |
| `Multi-mode` | One model exposes multiple interfaces, such as policy, forward dynamics or inverse dynamics; not every mode runs in every control loop. |
| `Search`, `Simulator`, `Execution`, `Post-training`, `Support`, `Evaluation` | The main contribution is a planner, simulator, execution mechanism, learning procedure, reusable component or evaluation, rather than a new standalone policy. |
| `Predictive supervision` | The reported claim concerns future supervision; this compact entry does not assert that a deployed predictor was removed or retained. |

Historical `Strict VAM: Yes / Partial / No` labels are preserved as the earlier curator's heuristic, **not a standardized field-wide definition or evidence of inference-time prediction**. New entries state mechanism and deployment explicitly. The old data tags are inherited; new topic tags do not imply undocumented camera setup, action labeling or data collection protocols.

New dates come from arXiv **first-submission metadata**; a separate revision date is shown when different. An arXiv ID's month and a local folder date are not used as substitutes. Titles and dates were checked against official arXiv metadata; resource links are author-supplied, and a repository link is not a claim of runnable implementation. `-` means no resource URL was confirmed in the metadata reviewed, not that no code exists. Route/deployment assignments are editorial readings of the papers. Reported gains remain specific to each paper's protocol.

## 🕹️ VAM-RL and Post-training View

This view includes several learning families. **RL, preference learning, distillation, supervised self-training and test-time adaptation are distinct mechanisms.** Historical boundary entries below do not imply that every update is reinforcement learning.

| Paper | Base route reading | Optimization mechanism | Why it gets the VAM-RL tag |
| --- | --- | --- | --- |
| [VAMPO](https://arxiv.org/abs/2603.19370) | `R1` | `GRPO` post-training of a VPP-style video predictor with Euler Hybrid sampling | the staged predictive-latent actor remains intact, so the novelty is RL post-training that sharpens control-relevant visual dynamics |
| [NoiseGate](https://arxiv.org/abs/2605.07794) | `R2` | `GRPO` trains a lightweight gate-policy network over per-latent denoising timesteps | the joint WAM backbone remains intact, while task success learns how much imagined future each action-denoising step should trust |
| [SANTS](https://arxiv.org/abs/2605.27947) | `Support / R2` | PPO-style training of a state-adaptive scheduler over video denoising depth and jump size | the WAM backbone remains frozen while RL learns which intermediate future state is most action-useful, making inference scheduling a control objective rather than a generic sampler shortcut |
| [EVA](https://arxiv.org/abs/2603.17808) | `R1 / R4` | `Flow-GRPO` with IDM-derived executability rewards over staged video planning rollouts | the paper keeps video-world-model planning and IDM action recovery intact, but optimizes the generator toward more executable futures |
| [WoVR](https://arxiv.org/abs/2602.13977) | `Support / R4` | `masked GRPO` inside a controllable video world model with Keyframe-Initialized Rollouts and low-frequency policy-world co-evolution | the backbone remains a world-model-based simulator for VLA post-training, while the novelty is reliability-aware RL that explicitly regulates hallucination and distribution shift |
| [ReWorld](https://arxiv.org/abs/2601.12428) | `Support / R4` | PPO-style post-training of embodied world models with a multi-dimensional preference reward model | the backbone remains a video-based embodied world model, while the headline contribution is reward modeling plus RL alignment toward physical realism, task logic, and embodiment plausibility |
| [AIM](https://arxiv.org/abs/2604.11135) | `R2` | self-distillation RL with dense ASVM reward and sparse task-success reward while freezing the video/value-map branches | the backbone remains a joint video-action model with an explicit spatial value-map bridge, while RL sharpens the action head to follow the future-grounded value map in closed-loop control |
| [ViVa](https://arxiv.org/abs/2604.08168) | `R4` | video-generative value modeling for robot RL, with future dynamics used as the value-estimation substrate | the value model is trained to anticipate embodied futures before scoring behavior, so the optimization signal becomes world-model-derived rather than a static state score |
| [RoboAlign-R1](https://arxiv.org/abs/2605.03821) | `R4` | `GRPO` with a distilled multimodal robot-video reward and sliding-window re-encoding | the video world model is optimized toward instruction following, manipulation success, contact, and physics signals instead of reconstruction-only metrics |
| [Hi-WM](https://arxiv.org/abs/2604.21741) | `Support / R4` | human corrective post-training inside an action-conditioned world model with rollback, branching, and later real-world consolidation | the world model becomes the post-training substrate that turns human interventions into reusable imagined correction data rather than one-off offline labels |
| [WAM-RL](https://arxiv.org/abs/2606.17906) | `Support / R4` | Flow-SDE actor RL with reconstruction-based dense rewards plus online video SFT of the world model with KL regularization | the WA backbone remains a world-model-plus-actor system, while online RL co-optimizes imagined futures and executable actions from environment feedback |
| [SafeDojo](https://arxiv.org/abs/2606.20698) | `Support / R4` | safety-constrained `GRPO` over an interactive video world model, using imagined task reward and safety cost with Lagrangian balancing | the world model supplies imagined rollouts and reward/cost estimates, so policy improvement is explicitly RL-based and safety-constrained rather than only supervised VLA fine-tuning |
| [MV-WAM](https://arxiv.org/abs/2606.21088) | `R2 / R4` | manifold-aware multi-objective training with Monte-Carlo progress-value tokens and value-guided rollback during online execution | the model jointly predicts video, actions, and value, the value signal monitors progress/misalignment and actively regulates recovery, making it a value-optimization boundary case for the VAM-RL view |
| [World Value Models](https://arxiv.org/abs/2606.24742) | `R4` | world-model-backed value-flow training with video/value DiT MoT coupling, value prefix randomization, and downstream use in AWR / Filtered BC | it repurposes temporal/future-planning priors from video world models into a generalist value signal that improves robot policy learning from mixed-quality data |
| [WorldSample](https://arxiv.org/abs/2607.02431) | `Support / R4` | closed-loop real-robot RL with world-model synthetic replay and Policy-Paced Learning | the world model generates counterfactual replay around real rollouts, while policy-paced scheduling controls when synthetic experience is trusted during real-robot RL |
| [HALO-WA](https://arxiv.org/abs/2607.04265) | `R3 / Support` | online actor-critic adapter trained over frozen WA reference actions and visual latents | the WA backbone stays frozen, so the optimization target is a lightweight latent-guided adapter that turns WAM foresight into fast precision adaptation |
| [WAM-TTT](https://arxiv.org/abs/2607.06988) | `Support / R4` | test-time training writes human demonstration videos into frozen-WAM fast-weight memory | it is not classic RL, but it belongs as a VAM-RL boundary case because deployment-time optimization changes how the frozen WAM conditions action generation from raw human video |
| [JoyAI-RA 0.5](https://arxiv.org/abs/2608.05674) | `R3` | inner-outer-loop reinforcement couples efficient task adaptation with foundation-policy improvement | RL is an explicit post-alignment stage over a latent-action-conditioned world/action backbone |
| [WNM-3D](https://arxiv.org/abs/2608.07267) | `R2` | Counterfactual DanceGRPO after world-action SFT and DAgger adaptation | RL refines the same 3D-conditioned joint future-view/action generator for closed-loop navigation success and path efficiency |
| [SimWAM](https://arxiv.org/abs/2608.07468) | `R2` | reinforcement learning with a compositional driving reward | the training-time video expert remains the dynamics prior while RL optimizes the deployable action-only planner beyond trajectory imitation |
| [Dream2Reward](https://arxiv.org/abs/2608.18787) | `R4` | online SAC and offline Q-guided policy optimization with a successful latent-transition alignment reward | the learned reward predicts task-conditioned successful future change and scores actual transitions by direction and magnitude, making policy improvement explicitly world-transition-grounded |
